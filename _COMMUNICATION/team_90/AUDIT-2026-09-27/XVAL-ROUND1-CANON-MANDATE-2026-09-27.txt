## 4. The deliverable

As written, a careful builder will not get a real example through the real mechanism, and a confident one will ship a hardcoded patch and believe it complied.

What the site actually does: a Chapters inner page shows the parts named in its defaults file. ACF can replace non-empty fields on those existing slots, and only when the page’s type is absent from `ea_chapters_seeded_only_types()`. The filter removes a type from that list for every page of that type. It does not add a row. Home-only types read their own field keys and the home page is off limits. Mokesh is off limits. The legal pages are the other large unfrozen group, and they are off limits.

The mandate’s instructions aim at the filter and at “a real field rather than a PHP constant,” and they call a hardcoded patch a failure. The only way to put a type onto a page that does not already contain it is a new entry in the defaults array, which is PHP in the theme. That is the mechanism, and the mandate’s wording makes it look like the forbidden shortcut. The canon does not contain the `s{N}_` names, so “build from the canon without opening the theme” is not true of any inner-page type.

The likely compliant-looking failure: edit `repair-defaults.php` or paste a section into a template, deploy, run the gate, see exit 0, and report the example. The gate will not show that `/repair/`’s other sections changed, and `/repair/` is one of the eight deviation pages Nimrod is supposed to judge untouched.

Type 37 is the only type with zero live instances. It is also the one that requires a renderer that does not exist (`CONTENT-TYPES-CANON.md` lines 555–563). Building it is “many files,” which section 2 says means the session has left the mandate. The deliverable does not say “do not pick 37.”

An achievable reading, which the mandate never states: on one already-unfrozen page (learning, lectures, workshops, therapist-training, or thank-you), change one existing slot through its ACF field, using text that is already on the site.
