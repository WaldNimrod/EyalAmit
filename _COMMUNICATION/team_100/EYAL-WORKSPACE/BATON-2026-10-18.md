**תאריך:** 18 באוקטובר 2026. **נכון לתמה 1.5.160.**
**מי כותב:** הסשן של נימרוד (צוות 10), כתמיכה. **מי קורא:** סשן הקודקס על המחשב של אייל.
**המסמך הזה גובר** על `AGENTS.md` בתיקייה הזו ועל `FIRST-TASK-2026-10-08.md`, בכל מקום שהם סותרים אותו. הם נשארו כרקע. המשימה הנוכחית היא המסמך הזה.

## 1. מי אתה, ומה היעד

אתה סשן הקודקס על המחשב של אייל. הפונה היומיומי הוא אייל. מדברים איתו בעברית, קצר, על העמוד או על השאלה שלפניו.

נימרוד והסשן אצלו נשארים תמיכה. לא מעבירים אליהם כל החלטה. פונים אליהם רק במקרים שבסעיף 3.

היעד, בסדר הזה:

1. לסגור מול אייל את מה שעדיין פתוח: תשובות, תיקונים, וקבצים שהוא מוסר.
2. ליישם את זה על **אתר הבדיקה**, לפרוס, ולהראות לו את העמוד.
3. רק אחרי שאתר הבדיקה סגור בעיניו, ובאישור כתוב של נימרוד ביומן — עלייה לכתובת הראשית `https://eyalamit.co.il`.

העלייה לכתובת הראשית לא מתחילה מהסשן הזה לבד.

## 2. איך שני הצדדים רואים אותו דבר

לפני כל סבב עבודה:

```bash
git pull --rebase origin main
```

אחרי סבב ששינה קבצים, או אחרי שנגמרה שיחה עם אייל שיש בה החלטה:

```bash
git add <נתיבים מפורשים>
git commit
git push origin main
```

כללים:

- אין `git add -A`. אין `git push --force`.
- אם הדחיפה נדחית, מושכים שוב עם `--rebase` ודוחפים. לא דורסים.
- קומיט אחד לעניין אחד. ההודעה אומרת מה נסגר, לא «עדכון».
- סיסמאות, `local/.env`, `local/.env.upress`, ו־`.vscode/sftp.json` לא נכנסים לקומיט. הם ב־`.gitignore` בכוונה.
- חשבון הגיט על המחשב של אייל הוא `EYALAMIT1`. אם `git config user.name` או החשבון המחובר הוא `WaldNimrod`, עוצרים ואומרים לאייל. לא עובדים מחשבון של נימרוד על המחשב שלו.

היומן המשותף: `BATON-LOG.md` בתיקייה הזו. כל צד מוסיף רשומה בתחתית, לא מוחק רשומות קודמות. אחרי רשומה — קומיט ודחיפה, אחרת הצד השני לא רואה אותה.

## 5. חיבור ופריסה

המאגר לא משוכפל אל השרת, ולא אל שורש האתר ב־uPress. פריסה היא העלאת `site/wp-content` ב־FTP, מהמחשב, אחרי קומיט.

הסקריפט: `scripts/ftp_deploy_site_wp_content.py`. הוא מעלה את עץ העבודה של התמה ושל ה־mu-plugins. הוא מסרב לרוץ כש־`site/` מלוכלך, כדי שלא יישלח תיקון שלא נכנס לגיט. הוא לא מוחק קבצים בשרת.

החיבור נקרא מ־`local/.env.upress`. הקובץ הזה לא במאגר. בלי הקובץ על המחשב של אייל אין פריסה. לא ממציאים ערכים, לא מדביקים סיסמה בצ'אט, לא מכניסים את הקובץ לקומיט. אם הוא חסר: רשומה ביומן «חסר local/.env.upress», ועוצרים את הפריסה. שאר העבודה מול אייל ממשיכה.

שדות הקובץ: `docs/project/EYAL_ENV_VARS_REFERENCE.md` סעיף 2. נוהל: `docs/project/UPRESS_WORDPRESS_STANDARD_v2.md`.

לפני פריסה ראשונה מהמחשב הזה, אחרי שהקובץ הונח:

```bash
pip install -r scripts/requirements-upress.txt
python3 scripts/ftp_deploy_site_wp_content.py --dry-run
```

ואז, אחרי קומיט של השינוי:

```bash
python3 scripts/ftp_deploy_site_wp_content.py
```

שינוי ב־CSS או ב־JS: מעלים את `Version` ב־`site/wp-content/themes/ea-eyalamit/style.css` באותו קומיט, לפני הפריסה.

ה־Hub (העמודים תחת `/ea-eyal-hub/`) הוא מסלול נפרד, ורק כשמשתנים המקורות שלו:

```bash
python3 scripts/build_eyal_client_hub.py
python3 scripts/ftp_publish_eyal_client_hub.py
```

לא מריצים בנייה מלאה של ה־Hub בשביל תיקון תוכן באתר. בנייה מלאה שומטת קישורים מעמוד הבית של ה־Hub. ראו `_COMMUNICATION/team_100/S007/FORM-EYAL-CONTENT-GAPS-README.md`.

וורדפרס מנהל לא משנה את עמודי הליבה: העורך שם ריק או מציג טקסט שאינו באתר. גם התפריט הראשי לא נערך ממסך התפריטים. הניווט החי בקוד. פוסט חדש, ועמוד חדש שאינו עמוד ליבה, כן נכתבים בעורך. הפירוט: `GUIDE-FIRST-USE-2026-10-08.md`.
